# 노하우집 개발 백로그

- 기준일: 2026-08-03
- 기준 문서: `PRODUCT_SPEC.md`
- 현재 상태: 정적 HTML·CSS·JavaScript 화면 구현 단계
- 문서 목적: 아직 개발하지 않은 작업과 보류 항목을 우선순위별로 관리한다.

이 문서는 현재 화면에 이미 반영된 세부 UI 수정 이력이 아니라, 실제 서비스 개발과 이후 개선에 필요한 미완료 과제만 기록한다. 우선순위는 개발 착수 시 일정과 사업 상황에 따라 다시 확정한다.

## 1. 우선순위 기준

| 구분 | 의미 |
|---|---|
| P0 | 실제 서비스 출시와 결제·수강 제공에 반드시 필요한 기반 작업 |
| P1 | MVP를 안정적으로 운영하기 위해 필요한 핵심 작업 |
| P2 | 운영 효율, 성능과 사용자 경험을 높이는 후속 개선 |
| 보류 | 현재 MVP 범위에서 제외하며 별도 범위 확정 후 진행 |

## 3. P0 — 서비스 출시 필수

### B-001. 인증과 권한

#### 작업 범위

- 카카오 간편 로그인과 필수 동의 처리
- 사용자 이름과 전화번호 저장
- 사용자, 크리에이터와 플랫폼 운영자 역할 구분
- 서버 세션 또는 안전한 인증 토큰 관리
- 화면과 API 양쪽에서 소유권 및 접근 권한 재검증
- 미인증, 권한 없음, 잘못된 주소의 접근 제한 화면 연결
- 로그아웃, 탈퇴와 개인정보 보존 정책 적용

#### 완료 기준

1. 로그인 사용자의 역할과 소유 리소스를 서버에서 판별한다.
2. 다른 사용자의 결제, 수강 정보와 크리에이터 관리 데이터에 접근할 수 없다.
3. 인증 만료와 권한 오류에 안전한 복귀 경로를 제공한다.

### B-002. 데이터베이스와 API

#### 작업 범위

- `LectureContent`와 `Class`의 다대다 관계 구현
- 사용자, 크리에이터, 주문, 결제, 수강 권한, 영상 진도, 다운로드 이력 모델 구현
- 운영 안내, 라이브 일정, FAQ와 알림톡 설정 저장
- 생성·수정·조회·삭제 API와 목록 조회 조건 구현
- 주문, 결제, 환불, 수강 권한의 상태 변경 이력 보관
- 한국 시간 표시와 서버 저장 시간 기준 분리

#### 완료 기준

1. 새로고침과 재로그인 후에도 저장한 데이터가 유지된다.
2. 클래스가 정렬된 강의 콘텐츠 목록을 참조하고 같은 콘텐츠를 여러 클래스에서 재사용할 수 있다.
3. 화면에 표시되는 수치와 상태의 데이터 출처가 API 기준으로 일치한다.

### B-003. 결제, 주문과 수강 권한

#### 작업 범위

- PG 결제 요청과 완료 결과 검증
- 서버 기준 가격, 공개 상태, 모집 기간과 수강 조건 재검증
- 중복 주문과 중복 결제 방지
- 결제 완료 주문에만 수강 권한 생성
- 결제 실패, 취소와 환불 상태 이력 보관
- 비공개 또는 모집 종료 클래스의 신규 결제 차단
- 지정 기간 수강과 결제 즉시 수강의 권한 기간 계산

#### 완료 기준

1. 클라이언트가 전달한 가격이나 결제 성공 값만으로 수강 권한을 만들지 않는다.
2. 같은 결제 결과가 여러 번 전달되어도 주문과 수강 권한이 중복 생성되지 않는다.
3. 주문 상태와 내 학습의 수강 가능 상태가 항상 일치한다.

### B-004. 영상과 자료 파일 처리

#### 작업 범위

- 영상과 자료의 대용량 업로드
- 업로드 진행, 완료, 실패와 재시도 상태
- 영상 인코딩, 스트리밍용 파일과 썸네일 생성
- 영상 재생시간 확인
- 수강 권한이 있는 사용자만 사용할 수 있는 재생·다운로드 URL 발급
- 허용 형식과 용량의 클라이언트·서버 이중 검증
- 영상 강의당 최대 2GB, 자료 파일당 최대 50MB 정책 적용

#### 완료 기준

1. 업로드 실패 시 입력 정보가 사라지지 않고 다시 시도할 수 있다.
2. 공유된 고정 주소만으로 비인가 사용자가 영상이나 자료에 접근할 수 없다.
3. 영상 처리 상태가 관리자와 수강생 화면에 일관되게 반영된다.

### B-005. 공통 검증과 안정성

#### 작업 범위

- 필수값, 길이, 형식, 파일 용량, 날짜와 가격의 서버 검증
- 로딩, 빈 결과, 조회 실패, 저장 실패와 재시도 화면
- 결제, 환불, 삭제와 알림 발송의 중복 방지 키
- 중요한 상태 변경의 감사 로그
- API 오류 코드와 사용자 안내 문구 정리
- 핵심 흐름의 자동화 테스트

#### 완료 기준

1. 프론트 검증을 우회해도 잘못된 값이 저장되지 않는다.
2. 실패 원인을 구분해 안내하고 가능한 작업에는 재시도를 제공한다.
3. 결제와 권한 변경 같은 중요 작업은 처리 이력을 추적할 수 있다.

## 4. P1 — MVP 운영 완성

### B-006. 내 학습 화면을 클래스 목록과 상세 화면으로 분리

- 기록일: 2026-08-03
- 상태: 방향 확정, 현재는 개발하지 않음
- 대상: 수강생 화면 > 내 학습

#### 배경

현재 내 학습 화면은 클래스의 영상, 자료, 운영 안내와 FAQ를 한 화면에 함께 표시한다. 수강 클래스가 많아지면 클래스별 상세 영역이 계속 쌓여 스크롤이 지나치게 길어지고, 한 번에 렌더링하거나 불러오는 요소와 데이터가 많아져 초기 표시와 화면 상호작용이 느려질 수 있다.

#### 변경 방향

내 학습 첫 화면에는 수강 중이거나 수강했던 클래스를 요약 카드 또는 목록으로 표시한다. 사용자가 특정 클래스를 클릭하면 해당 클래스의 상세 화면에서 다음 정보를 확인하고 학습하도록 변경한다.

- 이어서 학습 및 진도
- 영상 커리큘럼
- 제공 자료
- 운영 안내와 일정
- 클래스 FAQ

목록 화면에서는 모든 클래스의 상세 정보를 동시에 렌더링하지 않고 선택한 클래스의 정보만 상세 화면에서 불러오고 표시한다.

#### 구현 시 결정할 사항

- 수강 중, 수강 예정, 수강 종료 클래스의 구분과 정렬 기준
- 별도 페이지 또는 현재 화면 내부 전환 중 상세 진입 방식
- 목록으로 돌아올 때 스크롤 위치와 선택 상태 유지 방식
- 마지막으로 보던 강의와 진도 상태 유지 방식
- 모바일에서 목록과 상세 화면 사이의 이동 방식

#### 완료 기준

1. 내 학습 첫 화면에는 클래스별 요약 정보만 표시한다.
2. 클래스를 클릭해야 해당 클래스의 상세 콘텐츠가 표시된다.
3. 선택하지 않은 클래스의 상세 영역은 최초 화면에서 렌더링하지 않는다.
4. 상세 화면에서 목록으로 돌아갈 때 기존 탐색 상태가 유지된다.
5. 수강 클래스가 많아져도 첫 화면 길이와 초기 표시 비용이 크게 증가하지 않는다.

### B-007. 실제 학습 진도와 이용 이력

#### 작업 범위

- 영상 재생 시작 시 `수강 중` 상태 저장
- 마지막 구간 또는 종료 이벤트 도달 시 `수강 완료` 처리
- 마지막 재생 위치 저장과 이어보기
- 자료 다운로드 이력 저장
- 클래스별 전체 진도 계산
- 환불 판단에 필요한 재생·다운로드 로그 제공

#### 완료 기준

1. 단순 버튼 클릭이 아니라 실제 재생 이벤트를 기준으로 상태가 변경된다.
2. 다른 기기나 재로그인 후에도 최근 재생 위치와 진도가 유지된다.
3. 운영팀이 환불 판단에 필요한 이용 이력을 확인할 수 있다.

### B-008. 환불과 고객센터 처리

#### 작업 범위

- 결제 내역에서 환불 대상 주문을 선택해 카카오톡 고객센터로 연결
- 운영팀의 주문, 영상 재생과 자료 다운로드 이력 확인
- 전액 환불, 부분 환불과 환불 제한 계산
- PG 환불 완료 후 주문, 환불과 수강 권한 상태 동시 갱신
- 실패, 재시도와 처리 이력 관리

#### 선행 결정

- `7일 이내`를 판단하는 정확한 마감 시각
- 부분 환불 금액의 원 단위 반올림 또는 절사 기준
- 카카오톡 채널 주소
- 상담 화면에 주문 식별정보를 전달하는 방식

### B-009. 크리에이터 관리자 실제 연동

#### 작업 범위

- 강의 콘텐츠와 클래스 생성·수정·삭제 저장
- 연결된 클래스가 있는 강의 콘텐츠의 수정·삭제 차단을 서버에서도 검증
- 이미지, 영상과 자료 업로드 연동
- 수강생 목록의 검색, 필터, 정렬과 서버 페이징
- 월별 매출과 클래스별 결제 수강생 조회
- 채널 정보와 정산 계좌 저장
- 저장 중, 성공, 실패와 미저장 이탈 상태 처리

#### 완료 기준

1. 화면의 제한 조건을 API에서도 동일하게 검증한다.
2. 목록 필터와 집계 수치가 같은 서버 데이터 기준을 사용한다.
3. 저장 실패 시 작성 내용이 유지되고 다시 시도할 수 있다.

### B-010. 알림톡 승인과 발송

#### 작업 범위

- 승인 완료 템플릿만 자동 발송
- 수정 재승인 중 기존 승인 템플릿 유지
- 중복 발송 방지
- 발송 성공, 실패와 재시도 이력

- 저장 또는 알림 실패 시 입력 유지와 재시도

### B-012. 보안, 개인정보와 운영 모니터링

- 접근성, 키보드 탐색과 모바일 화면 최종 점검

## 5. P2 — 후속 개선

### B-013. 실제 정산 예정액과 정산 내역

현재 화면의 순 결제액은 `결제 - 환불·취소`이며 실제 정산 예정액이 아니다. 아래 사업 기준 확정 후 개발한다.

- PG사 수수료
- 알림톡 비용
- 부가세
- 환불·취소 반영 시점
- 정산 주기와 지급 상태
- 정산 내역 다운로드 형식

### B-014. 대량 데이터 확장성

- 내 학습 클래스 목록의 페이지네이션 또는 점진적 로딩
- 수강생과 결제 내역의 서버 검색·필터·페이징
- 관리자 대시보드 집계 API와 캐시
- 긴 목록의 로딩 스켈레톤과 부분 실패 처리
- 실제 데이터 규모를 사용한 성능 측정

## 6. 보류 과제

### B-015. 플랫폼 관리자

`(1차 개발 제외)platform-admin.html`은 참고 화면으로만 유지한다. 정식 개발 범위가 확정되면 다음 항목의 권한과 운영 정책을 별도로 정의한다.

- 크리에이터 승인과 운영 상태
- 클래스 공개 상태 검토
- 주문과 수강 상태 확인
- 알림톡 승인
- 환불과 정산 관리
- 플랫폼 공통 설정

### B-016. MVP 제외 기능

아래 항목은 현재 MVP에서 제외한다. 필요성과 우선순위를 다시 검토한 뒤 개별 과제로 분리한다.

- 공식 기수 관리
- 모집 정원
- 클래스 카드 프로그레스바
- 클래스 유형 선택
- 크리에이터 문의 관리와 답변 대기 문의
- 대시보드 매출 추이와 오늘 할 일
- 인증 마크와 사회적 증거 수치
- 인기 클래스 푸터 링크
- 고객센터 대규모 FAQ 검색
- 플랫폼 수수료 노출
- 정산 내역 다운로드
- 프로필 배경 이미지

## 7. 권장 개발 순서

1. 사업 기준과 미확정 정책을 먼저 결정한다.
2. 인증·권한과 핵심 데이터 모델을 구현한다.
3. 결제·주문·수강 권한과 영상·파일 처리를 연결한다.
4. 수강생 화면과 크리에이터 관리자 화면을 실제 API에 연결한다.
5. 학습 진도, 환불, 알림톡과 운영 도구를 연결한다.
6. 대량 데이터 성능, 보안, 접근성과 운영 모니터링을 점검한다.

## 8. 모든 과제의 공통 완료 조건

- 화면과 서버에서 동일한 권한 및 검증 기준을 사용한다.
- 로딩, 빈 상태, 성공, 실패와 재시도 상태를 제공한다.
- 민감하거나 되돌리기 어려운 작업은 서버 재검증, 중복 방지와 이력을 적용한다.
- 키보드 탐색과 모바일 화면을 포함한 접근성 기준을 확인한다.
- 한국 시간 표시와 서버 저장 시간 기준을 구분한다.
- 핵심 사용자 흐름과 정책 예외에 자동화 테스트를 추가한다.
