KNOWHOWZIP · INFORMATION ARCHITECTURE / V2

영상형과 전자책형,
하나의 판매 구조 안에서

판매자를 나누지 않고 콘텐츠를 등록할 때 유형을 선택합니다. 영상형은 커리큘럼 중심으로, 전자책형은 책과 목차 중심으로 구성하며 결제·주문·권한·정산은 공통으로 관리합니다.

개정안 · 2026.11.26 · 이전 통합 목차 중심 제안을 대체

01. 구조 결정

크리에이터 계정 하나영상과 전자책을 모두 등록 가능
→
영상형 / 전자책형등록 화면과 이용 화면 분리
→
공통 판매 관리가격 · 기간 · 공개 · 결제 · 권한
1차 범위에서는 영상과 전자책을 한 판매에 혼합하지 않습니다. 첨부 자료는 영상형의 보조 콘텐츠이며, 전자책은 독립적으로 판매하는 주 콘텐츠입니다.

기존 ‘클래스 관리’는 ‘판매 관리’, ‘강의 콘텐츠’는 ‘콘텐츠 관리’로 확장합니다. 사용자에게는 유형에 맞게 ‘영상 강의’ 또는 ‘전자책’으로 표시합니다. 기존 클래스 ID와 구매 이력은 유지합니다.

04. 유형별 등록 흐름

영상형

콘텐츠 관리 → 영상형 선택
→ 제목·설명 → 영상·자료 구성 → 저장
→ 판매 관리 → 영상형 선택
→ 영상 콘텐츠 연결 → 가격·기간·공개 설정
→ 구매자: 학습하기 → 영상 플레이어

전자책형

콘텐츠 관리 → 전자책형 선택
→ 제목·설명 → PDF·목차 → 저장
→ 판매 관리 → 전자책형 선택
→ 전자책 1권 연결 → 가격·기간·공개 설정
→ 구매자: 읽기 → 전자책 뷰어

유형은 콘텐츠에 고정합니다. 영상형 판매에는 영상 콘텐츠만, 전자책형 판매에는 전자책만 연결합니다. 자료는 영상 학습을 돕는 다운로드 파일로 유지합니다.

06. 1차 범위와 결정할 정책

1차 구현 범위

  • 콘텐츠·판매 목록 유형 필터
  • 유형 선택 후 서로 다른 등록 화면
  • PDF 파일 검증 · 페이지 수 · 목차 입력
  • 동일 유형만 판매에 연결
  • 전자책 판매당 1권, 결제 즉시 열람
  • 전자책 기간 지정 또는 기간 제한 없음
  • PDF.js 뷰어 · 책갈피 · 이어읽기

후속 연동·정책

  • 사용자 판매 목록·상세·내 학습 유형별 연동
  • 인증·결제·비공개 파일 저장·서버 권한 확인
  • 전자책 열람과 환불 처리 기준
  • 구매자별 워터마크 · 파일 개정판 정책
  • 기기 간 읽기 위치·책갈피 동기화
  • 영상+전자책 혼합 판매 · 다권 묶음 · EPUB
다운로드·인쇄 버튼 미제공은 UI 제한입니다. 브라우저로 전달된 PDF의 저장·복제·캡처를 완전히 차단하는 보안 기능이 아닙니다.

이번 관리자 구현의 저장은 로컬 브라우저 미리보기입니다. 서버 업로드·실제 판매 공개·결제 처리를 실행하지 않습니다. PDF 50MB 제한과 판매당 1권은 1차 제안 기준입니다.
